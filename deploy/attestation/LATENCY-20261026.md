# Public SSH versus Tailscale attestation latency

Measured on 26 October 2026 IST after migration. Production remained on its working private route. The public comparison used a temporary source-restricted key, loopback reverse listener, queue and narrow public SSH ingress rule; these were removed afterward.

Both isolated queues used the same production helper and the same queue source/settings: concurrency16 and keepalive-off. Requests were serial and alternated public-first/Tailscale-first across 12 pairs per endpoint. Every request used a fresh local HTTP connection with an eight-second timeout. All 24 proof requests produced distinct valid proofs. No bearer or proof body was retained.

| Metric | Public SSH | Tailscale |
|---|---:|---:|
| Fresh proof median | 694.3 ms | 527.7 ms |
| Fresh proof mean | 707.9 ms | 551.0 ms |
| Fresh proof range | 627.8–899.7 ms | 523.9–679.8 ms |
| Health median | 643.5 ms | 749.5 ms |
| Health mean | 816.0 ms | 755.6 ms |

The paired mean proof difference was **−157.0 ms** for Tailscale. A bootstrap interval for that sample's paired mean was −213.0 to −105.3 ms. Health results were much noisier: paired mean −60.4 ms, interval −360.6 to +235.2 ms. This sample shows no added proof-request latency penalty; it does not establish a universal fixed network overhead or that Tailscale is intrinsically faster.

The path was relayed during measurement. Air's status displayed AWS's `iad` relay; AWS's status displayed Air's `blr` relay. Inner SSH TCP RTT snapshots were 266.8/254.6 ms for Tailscale and 300.7/289.7 ms for public SSH before/after the run. These are current-path observations, not guarantees across future networks or routing changes.

Production health remained200 before, midway through and after the comparison, and its queue failure counter did not increase.

Attestation is generated for a fresh Live session and reused for its sideband. This timing therefore applies to fresh sessions, replacements and auxiliary sessions. It is not a measurement of spoken reply latency: established conversation audio is not routed through the Air attestation tunnel. The existing 16-proof concurrency permits overlapping generation when multiple sessions start together.
